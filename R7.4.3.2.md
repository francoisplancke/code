# R7.4.3.2 — Citations et fiabilité des références

## Installation

Appliquer le ZIP à la racine du dépôt après R7.4.3.1. Exécuter :

```bash
psql "$DATABASE_DSN" -v ON_ERROR_STOP=1 --single-transaction -f migrations/006_extraction_cascade_review.sql
PYTHONPATH=. python3 -m pytest -q tests/unit/test_r7432.py tests/unit/test_extraction_cascade.py
```

## Changements

- `resolve_citation()` ignore les offsets proposés par les modèles et calcule les positions Python `[start,end)` d'une citation littérale unique.
- Recherche de secours strictement typographique : blancs consécutifs et apostrophes courantes. Les offsets sont remappés sur le texte canonique, puis la citation canonique est conservée. Pas de correspondance floue ni de reformulation admise.
- Les candidats non ancrables sont rejetés individuellement, avec diagnostic ; `anchored` compte les ancrages exacts et typographiques.
- Les comparaisons ne peuvent être `EXACT_FIELDS` que lorsque les deux extractions sont `SUCCESS` ou `EMPTY`.
- La cascade reçoit `NEEDS_REVIEW` si la référence n'est pas exploitable ; une telle source ne sera pas relancée automatiquement.
- `POLICY_VERSION = r7.4.3.2-silver-v1` : les traitements R7.4.3.1 restent en base mais peuvent être retraités **une seule fois** sous le nouveau protocole, pour corriger les échecs de validation antérieurs.
- Le sélecteur CLI utilise la constante `POLICY_VERSION`, évitant une version codée en dur.

## Prudence

- `COMPLETED` signifie une référence **techniquement exploitable**, pas une vérité juridique.
- Un `EMPTY` concordant ne prouve pas l'absence d'obligation ; calibrer ensuite le taux d'omission.
- Les anciennes lignes R7.4.3.1 ne sont pas modifiées ; ne pas les considérer automatiquement comme des références calibrées.
- Les erreurs d'API et la gestion de crédit existantes restent inchangées.
- Pas de migration automatique des obligations ou d'effacement des runs antérieurs.

# R7.4.3.1 — calibration multi-LLM (prototype contrôlé)

Requires R7.4.2.1 schema and `legal.llm.providers` from the project.

```
psql "$DATABASE_DSN" -v ON_ERROR_STOP=1 --single-transaction -f migrations/005_extraction_cascade.sql
PYTHONPATH=. python3 -m pytest -q tests/unit/test_extraction_cascade.py
PYTHONPATH=. python3 scripts/extract_cascade.py --jurisdiction EU --limit 10
PYTHONPATH=. python3 scripts/extract_cascade.py --jurisdiction FR --limit 10
```

Provider configuration: `LEGAL_LLM_LOCAL_URL`, `LEGAL_LLM_LOCAL_MODEL`,
`DEEPSEEK_API_KEY`, `LEGAL_LLM_DEEPSEEK_MODEL`, `GEMINI_API_KEY`,
`LEGAL_LLM_GEMINI_MODEL`. Check local endpoint URL and models first.

**Important limitations:**
- DeepSeek is called for every source as the automatic silver reference.
- Gemini is called on field disagreement or partial extraction, not for independent
  audits of apparent agreement (add randomized audit before claiming calibrated accuracy).
- Exact field comparison is a conservative proxy; paraphrases can cause false disagreements.
- A COMPLETED source is skipped only for the same jurisdiction, source ID, text checksum,
  and policy version. A changed source/policy can be processed again.
- FAILED and CREDIT_EXHAUSTED rows are skipped unless `--retry-failed` with explicit IDs.
- RUNNING rows require inspection/reset after worker crash; no automatic takeover.
- HTTP 402 and explicit provider quota/billing errors stop the script (exit 42).
  HTTP 429 rate limiting alone is not proof of exhausted credits; generic 403
  may be a permissions issue. If providers obscure the billing reason, stop on
  the ordinary error and inspect provider dashboard.
- Existing `extract_and_store` holds a DB transaction during the LLM call; this
  prototype is sequential and should be refactored before multi-worker deployment.
- For large corpora, select EU/FR provisions linked by verified NIM mappings
  rather than using the default ordered sample.
- No legal validity claims; model consensus is not ground truth.

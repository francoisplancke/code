# R7.4.2.1 — Stabilisation et vérification à la demande

Patch construit à partir de `code-main (3).zip` (archive complète).

## Prérequis

La migration `migrations/003_verification_status.sql` du dépôt doit être appliquée **une seule fois**. Aucun changement de schéma additionnel requis.

## Vérification à la demande

```bash
set -a; source /etc/code/legal.env; set +a
PYTHONPATH=. python3 scripts/check_obligation_evidence.py ebda9c23-bfa6-4680-8f36-7c11b6bfa341
```

La première vérification est persistée dans `legal_obligation_evidence_check`. La suivante renvoie `cached: true`, tant que la source, les champs de preuve et la version du validateur sont identiques. `--force` recalcule. `VERIFIED` n'atteste **que la cohérence textuelle**, jamais la qualification juridique.

Dans l'application, appeler `ensure_evidence_checked(conn, obligation_id)` avant utilisation pour R7.4.3 et ne transmettre automatiquement que les résultats `VERIFIED`. La fonction ne fait pas `commit` : le gestionnaire de connexion/transaction doit le faire.

## Extraction LLM

- Chaque candidat est validé séparément, sans impression du JSON brut en console.
- Les candidats rejetés sont comptabilisés avec leurs motifs et indices dans `legal_obligation_run.parameters.validation`.
- `outcome` vaut `SUCCESS`, `EMPTY`, `PARTIAL` ou `FAILED_VALIDATION` ; la colonne `status` existante conserve son contrat `SUCCEEDED` / `FAILED`.
- Une erreur de transport, un JSON non analysable ou une erreur SQL restent des exceptions et provoquent un rollback (pas de run conservé).
- L'API `llm_extract` conserve son tuple `(items, response)` ; un dictionnaire `diagnostics` optionnel reçoit les rejets.
- Aucun appel LLM pour la vérification des preuves.

## Tests

```bash
python3 -m pytest -q tests/unit/test_obligation_extract.py tests/unit/test_obligation_evidence.py
```

## Limites

Le statut du contrôle est mis en cache mais recalculé si la source ou les champs de preuve changent. Un changement de champs sémantiques (`action`, `modality`, etc.) n'invalide pas la vérification **textuelle** car celle-ci ne valide pas ces champs. L'extraction n'effectue pas de revue juridique et n'évalue pas la justesse de la qualification.

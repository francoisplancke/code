# R7.4.1 — Contrat d'obligation juridique

Ce jalon définit **le stockage et le contrat d'échange**, pas un extracteur LLM ni un détecteur de surtransposition.

## Migration

Sur une base contenant déjà `version` (LEGI) et `eu_provision` (UE) :

```bash
psql "$LEGAL_DSN" -v ON_ERROR_STOP=1 -f migrations/002_legal_obligations.sql
```

Migration idempotente pour une base existante. Sauvegarder la base avant toute migration. Ne pas exécuter avant l'import LEGI et UE.

## Modèle

- `legal_obligation_run` : version du pipeline, méthode, fournisseur, modèle, paramètres, statut et horodatages.
- `legal_obligation` : obligation dérivée, lien vers **exactement une** source (`version.id` ou `eu_provision.provision_id`), empreinte du texte source, citation et offsets, éléments sémantiques, preuves, score facultatif et état de revue humaine.
- `source_checksum` est fourni par le futur extracteur ; une obligation n'est pas automatiquement réputée actuelle si le texte source a changé.
- Les offsets sont des positions de caractères Unicode dans le texte source, début inclus et fin exclue. Le validateur peut vérifier l'extrait par rapport au texte original.
- Les champs `raw_output`, `evidence` et `confidence` sont des données dérivées ; aucune conclusion juridique n'est présumée validée.
- Les FK vers les sources utilisent `RESTRICT` pour éviter d'effacer silencieusement les preuves lors d'un réimport.

## Contrat JSON (sortie d'un extracteur)

`legal.obligations.OBLIGATION_JSON_SCHEMA` et `validate_obligation(payload, source_text=...)`.

Tous les champs sont obligatoires, les champs facultatifs ont la valeur `null` ; `conditions` et `exceptions` sont des tableaux de chaînes. Aucun champ supplémentaire n'est accepté. Le modèle n'est **pas autorisé** à décider de son identifiant de source, de son run, de sa confiance ou de son statut de revue.
